## Slide 2 — 问题与动机
- 航空公司竞争激烈，用户反馈数据海量且分散
- 纯人工竞品分析效率低、主观性强
- LLM 可以把大量非结构化评论转为结构化洞察
- 但运营决策还缺少“价格”和“需求/客流”一体化数据支撑

---

## Slide 3 — 行业范围界定
- 研究对象：欧洲客运航空（短途/中途航线）
- 对比类型：
  - 全服务航司：Lufthansa、Air France、KLM
  - 低成本航司：Ryanair、easyJet、Wizz Air
- 数据视角：德语与英语用户评论 + 市场价格与需求指标

---

## Slide 4 — 文献基础 1（Porter）
- 用 Five Forces 搭建市场竞争结构
- 在航空场景下的关键点：
  - 同业竞争强（价格、航线网络、时隙）
  - 用户议价能力高（比价透明）
  - 进入壁垒高（机队、时隙、监管）

---

## Slide 5 — 文献基础 2（IPA + Kano）
- 区分用户需求中的“基础项、绩效项、兴奋项”
- 对航空服务的映射：
  - 基础项：安全、准点、规则透明
  - 绩效项：价格-服务性价比、问题处理效率
  - 兴奋项：智能改签、优质数字化体验

---

## Slide 6 — 文献基础 3（LLM-Cure）
- 用 LLM 从评论中抽取优势/劣势和证据句
- 支持多竞争对手标准化评分
- 为本项目提供可复用的方法范式

---

## Slide 7 — 初始分析维度
1. 准点率与可靠性
2. 票价与收费透明度
3. 客服与航变处理能力
4. 数字体验（App/Web/自助服务）
5. 乘机体验（登机、行李、舒适度）
6. 退改签效率与公平性

用于决策支持的扩展维度：
7. 航线-时段价格水平（含价格弹性）
8. 需求指标（客流代理、搜索/预订趋势、供需缺口）

## Slide 8 — 工具方案：FlightScope AI
工作流：
1. 选择航司 + 航线 + 时间范围 + 数据来源
2. 多源采集：评论 + 价格时间序列 + 需求/客流代理数据
3. 双层分析：LLM 文本洞察 + 预测/运筹规则引擎
4. 可视化输出：对比雷达图、排名、趋势与运力建议

软件架构（你负责讲）：
- **BYOK（用户自带 Key）**：用户可在 UI 输入自己的 API Key
- **Fallback 到 OpenRouter**：主通道不可用时切换到 OpenRouter
- **收益**：降低单一模型依赖，演示更稳定，扩展更灵活

端到端流程含义（老师易懂版）：
- **输入**：明确比较对象、时间、航线和来源
- **采集**：自动抓取原始数据并做清洗
- **分析1（LLM）**：将文本转成可比较维度与证据
- **分析2（Forecast/OR）**：估计需求压力与供给缺口
- **输出**：给出可执行建议而不只是“看图”

UI 设计：
- **侧边栏 API & Engine**：Key 输入、模型通道选择、连接测试
- **控制区**：航司/航线/时间/来源选择，Run Analysis
- **结果区 Tabs**：
  - Overview（KPI + 雷达图）
  - Dimension Ranking（分维度排名）
  - Head-to-Head（两家航司深度对比）
  - Evidence（证据句与问题模式）
  - Capacity Planner（增减班次、机型与时段建议）

## Slide 9 — MVP 与价值
MVP 功能：
- 4-8 家航司对比雷达图
- 分维度证据化排名
- 两家航司 Head-to-Head 对比
- 关键主题时间趋势
- 航线级价格与需求监控（试点）
- 首版规则建议：**Add / Hold / Reduce Flight**

MVP 的含义：
- 不是最终完整产品
- 是最小可用版本，先验证核心价值
- 即便只覆盖 2-4 家航司，也能形成可行动洞察

业务价值：
- 更快、更客观的竞争分析
- 提前识别服务风险与差异化机会
- 直接支持运营问题：
  - 在时间点 t、航线 r 是否该加班次？
  - 应上多大机型？
  - 哪个时段更优？

## Backup Slide A — Capacity Planner 逻辑（Input -> Rule Engine -> Output）

目标：
- 对航线 r 在时间点 t 给出 **Add / Hold / Reduce**
- 输出机型级别与推荐时段

输入特征：
- 航线-时段价格水平与价格变化
- 需求代理（搜索热度、预订代理、评论量）
- 供给侧（当前班次、周座位数、竞争对手投放）
- 运行质量（准点率、取消率、服务压力）
- 日历因素（周内/周末、节假日、季节）

规则引擎（MVP，强调可解释）：
- 步骤1：计算 Demand Pressure Score
- 步骤2：计算 Supply Gap Score
- 步骤3：计算 Profitability Proxy
- 步骤4：根据运行风险做折减
- 步骤5：汇总 Final Score 并输出决策

简化决策逻辑：
- 需求高 + 供给缺口为正 + 风险可控 -> **Add Flight**
- 指标中性 -> **Hold**
- 需求弱或运行风险高 -> **Reduce / 不扩张**

机型建议（MVP）：
- 中等需求增量 -> 小型窄体机
- 高需求且高峰时段 -> 中/大型窄体机
- 不确定性高 -> 先加频次再评估升舱位

时段建议：
- 需求强且准点稳定 -> 优先高峰时段
- 价格敏感且成本压力高 -> 测试次高峰/非高峰窗口

UI 输出：
- 航线决策卡片（Add/Hold/Reduce）
- 机型建议 + 时段建议
- Top-3 数据依据 + 置信度分数
